This project evaluates whether a machine learning model can help a content team prioritize the pages most likely to improve engagement, while remaining grounded in realistic business constraints, honest evaluation, and safe data practices.

1. Problem framing

Large content libraries include pages with strong performance and pages that receive traffic but fail to convert interest into engagement. Without a data-driven queue, teams often choose pages based on recency, memory, or intuition. That creates wasted effort and missed opportunities.

Unit of analysis
One content piece measured over a rolling 90-day window.
Output
A ranked list of content pieces with scores and ordering.
Action
Editorial teams review top-ranked pages and decide what to improve.
Risk
False positives waste effort; false negatives miss hidden opportunities.
The goal is not to auto-edit content, but to support better human decisions with a ranked queue that highlights the strongest opportunities.

2. Data safety

The analysis draws from the FlyRank internship warehouse, a real-world dataset of 30,000 content pieces collected over a single 90-day period and hosted on Hugging Face. The dataset is pseudonymous and contains no direct identifiers like author names or domains.

We used exactly seven features to predict engagement: content type, position tier, freshness tier, word count, competition level, CPC, and search volume. Several columns were intentionally excluded because they represented leakage, including variables derived from the target or overlapping with the label window.

This is a single 90-day snapshot, which means the analysis is limited to that time window and does not capture longer-term seasonal effects.

3. Baseline

Before building a model, we created a transparent baseline rule based on impressions, CTR, and position quality. It was designed to be simple enough for a human team to understand and explain.

4. Model / analysis

A Random Forest Regressor was selected because it handles mixed data types well, tolerates missing values, and provides interpretable feature importance. The preprocessing workflow was intentionally simple: categorical values were filled with “MISSING,” numeric values with the median, and no scaling or additional feature engineering was applied.

Feature list

  1. content_type
  2. position_tier
  3. freshness_tier
  4. word_count
  5. competition_level
  6. cpc
  7. search_volume

The target variable was engagement_rate, measured as (engaged_sessions_90d / total_sessions_90d) × 100.

5. Evaluation

A grouped-by-client split was used instead of a random split to reduce optimistic results from client-specific patterns leaking into training. The model and baseline were then evaluated using the same metric: mean engagement in the top-ranked items.

Evaluation cutoff Baseline Model
Top 20 2.3415 0.3780
Top 50 2.9996 1.5798
Top 100 3.6169 2.5390

The key result is that the baseline outperformed the model at all three cutoffs. The model did not beat the baseline on this honest split, and the error pattern suggests that it under-ranked some of the highest-potential pages.

6. Recommendation

The practical takeaway is not to discard machine learning, but to use it as one input alongside business context. The highest-value editorial actions are likely to occur where content has strong visibility but weak engagement, such as high-impression pages with low CTR.

The recommended editorial playbook is to prioritize pages with large reach but weak click-through or engagement signals, then improve metadata, framing, and content structure. Confidence is highest for these strong traffic signals, while later-tier recommendations are weaker and more exploratory.

7. Reproducibility

The project is designed to be reproducible. The repository includes a sequence of notebooks and analytical steps to validate the pipeline, and the model uses a fixed random seed of 42 for consistent split and training behavior.

Required libraries include pandas, scikit-learn, numpy, and matplotlib. To reproduce the work, clone the repository, install dependencies, accept the Hugging Face dataset gate, then run the notebooks in order.
