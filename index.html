Capstone Report — Machine Learning

Author: Reezcon Vivo Repo: First-ML-Pipeline Date: September 2026

Managing a website with more than 30,000 content pieces is difficult without a disciplined prioritization strategy. This project explores whether a machine learning model can help a content team identify the pieces most likely to improve engagement, while respecting data quality, leakage controls, and realistic editorial decision-making.

1. Problem framing

A large content catalog often contains a mix of pages with strong performance and pages that are visible but underperforming. Without data, teams often make subjective decisions: fixing the oldest pages, the ones they remember writing, or the ones with the most attention-grabbing headlines. These heuristics waste time and may miss the content with the highest improvement potential.

Unit of analysis One row represents one content piece measured over a trailing 90-day window.
Output A ranked queue of content pieces with a score and rank for prioritization.
Action A content manager reviews the top-ranked items and decides whether to improve titles, refresh content, or improve SEO structure.
Cost of a wrong call: a false positive wastes editorial time; a false negative means a high-potential opportunity may remain unaddressed.

Machine learning helps because engagement is influenced by multiple signals at the same time, including content type, position, freshness, word count, CPC, search volume, and competition. These variables interact in complex ways, making a data-driven ranking tool more useful than a single-rule heuristic.

2. Data safety

The analysis uses the FlyRank internship warehouse, a real-world dataset of 30,000 content pieces collected over a single 90-day period and hosted on Hugging Face. Access is available here: https://huggingface.co/datasets/FlyRank/internship-warehouse. Client and content identifiers are pseudonymous, protecting real names and domains.

We used exactly seven features to predict engagement:

  1. content_type
  2. position_tier
  3. freshness_tier
  4. word_count
  5. competition_level
  6. cpc
  7. search_volume

Several columns were intentionally excluded because they represented leakage, including information derived from the label itself, or metrics that overlapped with the 90-day target window. We also avoided two common forms of leakage: using future or overlapping engagement variables and using attributes vulnerable to target contamination.

The dataset also has an important structural limitation: it is a single 90-day snapshot. That means the analysis cannot capture full seasonal trends or longer-term content dynamics.

3. Baseline

Before model development, we built a simple baseline rule intended to be understandable to a human content team. It flags content with high impressions and poor engagement signals.

The baseline score was encoded as: baseline_score = 3×(high_impr) + 2×(med_impr) + 2×(low_ctr) + 2×(poor_position) + 1×(missing_position) with thresholds for high impressions, medium impressions, low CTR, and poor position.

2.3415 Baseline top-20 mean engagement
2.9996 Baseline top-50 mean engagement
3.6169 Baseline top-100 mean engagement
2.91 Base rate

This is a fair comparison because it uses the same data, metric, and test set as the model, while staying transparent and operationally understandable.

4. Model / analysis

The chosen model was a Random Forest Regressor, selected for its ability to work well with mixed categorical and numeric data, handle missing values, and expose feature importance in a relatively interpretable way.

Preprocessing

  • Categorical features were filled with "MISSING".
  • Numeric features were filled with the median.
  • No scaling, transformations, or extra feature engineering were applied.

Exact feature list

  1. content_type
  2. position_tier
  3. freshness_tier
  4. word_count
  5. competition_level
  6. cpc
  7. search_volume

The target variable was engagement_rate, a continuous metric from 0 to 100 defined as:(engaged_sessions_90d / total_sessions_90d) × 100.

5. Evaluation

A grouped-by-client split was used rather than a random split because content strategy, editorial maturity, and search performance differ substantially across clients. A random split would allow the model to learn client-specific patterns that overstate performance.

Metric Baseline Model
Top-20 mean engagement 2.3415 0.3780
Top-50 mean engagement 2.9996 1.5798
Top-100 mean engagement 3.6169 2.5390

The most important conclusion is that the baseline outperformed the model at every evaluation cutoff. The model was not able to beat the baseline on this honest split, and the error pattern suggests that it systematically under-ranked the most promising pieces.

6. Interpretation

Feature importance showed that word_count was by far the strongest signal, representing approximately 61.7% of the model's predictive value. This means longer pieces are associated with higher engagement, though it is still unclear whether longer content causes better engagement or simply correlates with stronger topic coverage and stronger editorial depth.

An unexpected result was that position_tier did not dominate the model, despite its apparent importance in search marketing. This may reflect overlap with other variables such as content quality, competition, and search intent.

7. Recommendation

The ranked queue from this analysis supports a practical editorial decision framework. The highest-priority items are those with high impressions and weak engagement signals: pieces that receive visibility but fail to convert interest into clicks and engagement.

The first tier of action should focus on pages with high impressions and low CTR, where the team should improve titles, meta descriptions, and framing. Confidence is highest in these cases because the traffic signal is strong and the operational fix is concrete.

Lower-confidence recommendations should be treated as exploratory rather than definitive, because weaker signals can be noisy and highly context-sensitive.

8. Reproducibility

  1. Clone the repository.
  2. Install the required Python packages.
  3. Accept the Hugging Face dataset gate and create a read-only token.
  4. Run the notebooks in order: research question, ML task framing, data contract, baseline score, model training, signal audit, and action playbook.
  5. Re-run the final outputs and verify generated files.

The required Python packages are: pandas, scikit-learn, numpy, and matplotlib. The random seed for the model and split is 42, ensuring reproducible train/test splitting and model training.
